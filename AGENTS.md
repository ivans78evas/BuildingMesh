# ИНСТРУКЦИИ ДЛЯ АГЕНТА (BUILDINGMESH)

Этот файл содержит критически важные правила разработки проекта BuildingMesh. Агент ОБЯЗАН следовать им.

## 1. ПРАВИЛА РАЗРАБОТКИ (Definition of Done)
- **UI/UX:** Весь интерфейс должен быть выполнен в темной инженерной стилистике (Dark Mode) with 'JetBrains Mono' font.
- **Backend:** Каждая бизнес-сущность (Project, Wall, Issue) должна иметь:
  - Свой эндпоинт в API v1.
  - Описание в Swagger (аннотации в коде).
  - Миграцию в `backend/migrations/`.
- **Infrastructure:** Все пароли, порты и URL должны читаться из ENV.

## 2. ПРОВЕРКА ПЕРЕД КОММИТОМ (Verification Steps)
Перед каждым `submit` агент обязан выполнить:
1. `cd backend && go build ./...` — проверка компиляции.
2. `grep "Compare Reality" backend/cmd/server/web/index.html` — проверка наличия продвинутого UI.
3. `swag init -g cmd/server/main.go -o docs` — обновление документации.

## 3. СТРОГИЕ ЗАПРЕТЫ
- ЗАПРЕЩЕНО использовать `AutoMigrate` от GORM или аналоги. Только SQL-миграции.
- ЗАПРЕЩЕНО оставлять старые версии файлов (например, `saas.html` или папки `static`), если они заменены на `cmd/server/web`.
- ЗАПРЕЩЕНО имитировать работу фронтенда, если он не связан с API.

## 4. ЮРИДИЧЕСКАЯ И АРХИТЕКТУРНАЯ ЧИСТОТА (IP PROTECTION)
- **Twenty Integration:** Twenty используется исключительно как изолированное Headless-ядро (Backend-as-a-Service).
- **Лицензионная изоляция:** Наш проприетарный код (обработка LiDAR, RuView CSI, алгоритмы 3DGS) НЕ ДОЛЖЕН содержать в себе части кода Twenty или наследоваться от его классов напрямую, чтобы избежать вирусного действия лицензии AGPL-3.0.
- **Proxy-патерн:** Взаимодействие с Twenty происходит строго через API/GraphQL или шину данных (Redis/RabbitMQ).
- **Цель:** Система готовится к последующей продаже. Архитектура должна позволялять легкую замену Twenty на любое другое ядро (например, кастомный PostgreSQL или Salesforce) без переписывания бизнес-логики обработки данных со стройки.

## 5. JULES AUTONOMOUS PIPELINE & ENTERPRISE DEPLOYMENT (DEBIAN 13)

This section defines the mandatory automation protocol for the AI Agent (Jules) within the BuildingMesh ecosystem. Jules MUST execute these steps sequentially, verify checkpoints, and output standardized deployment playbooks.

### 5.1. High-Precision Code Verification & IP Protection Audit
Before any deployment or update approval, Jules must autonomously execute and validate the following pipeline inside the hybrid workspace:

1. **Strict Core & IP Boundary Check**:
   - Verify that the **Go 1.23 Engine** (handling heavy LiDAR/CSI data) does not import, inherit, or compile any code from the Twenty CRM repository.
   - Assert that all mutations and metadata synchronizations with Twenty CRM are isolated behind the **Proxy Pattern** via REST/GraphQL endpoints or RabbitMQ channels to secure our proprietary algorithms from AGPL-3.0 licensing.

2. **Technical Stack Compilation & Quality Assurance**:
   - Run compilation and safety checks: `cd backend && go test ./...` and `go build ./...`. Ensure the SQLite driver (`modernc/sqlite`) builds flawlessly without CGO dependencies.
   - Validate Three.js build targets within the React-based Engineering Console (`Engineering Console`).
   - Confirm strict Node.js/TypeScript ESM compliance: Ensure all relative backend/frontend imports explicitly use the `.js` extension.
   - Scan for multi-tenant data isolation: Every SQL query, Go struct, or API interaction mapping to `Project`, `Wall`, or `TemporalScanLayer` MUST explicitly filter by `organization_id`.

3. **Data Model Integrity (Layer Time-Machine & Git-like Commits)**:
   - Verify that any update to the database layer supports chronological tracking (`TemporalScanLayer`).
   - Ensure that once an `InspectionCommit` achieves a high quality score and approval, its database entity state triggers an immutable freeze (`Read-Only` status flag).

### 5.2. Target Remote Environment Specifications (Debian 13)
The production deployment must target and optimize for the following cloud/on-premise topology:
- **OS**: Debian 13 (Trixie) x86_64 Core.
- **Containerization (Coolify Pattern)**: Managed via `Dockerode` or standard Docker Compose. The Go engine, RabbitMQ, Redis, and Headless Twenty CRM must run in isolated containers.
- **Resource Constraints**: Strict multi-tenant limits enforced via Docker Compose quotas (e.g., maximum limits per Actor instance to prevent I/O bottlenecks during LiDAR point-cloud processing).

## 6. ВЫСОКАЯ НАГРУЗКА И БИНАРНЫЕ ДАННЫЕ (SCALABILITY)
- **Запрещено:** Хранить Point Clouds, CSI-матрицы или панорамы 360 в SQLite.
- **Обязательно:** Использовать `S3Service` для сброса всех файлов > 1MB во внешнее хранилище.
- **Обязательно:** Использовать RabbitMQ для демпфирования пиковых нагрузок при загрузке данных. API должен отвечать `202 Accepted` сразу после сохранения сырого файла.
