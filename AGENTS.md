# ИНСТРУКЦИИ ДЛЯ АГЕНТА (BUILDINGMESH)

Этот файл содержит критически важные правила разработки проекта BuildingMesh. Агент ОБЯЗАН следовать им.

## 1. ПРАВИЛА РАЗРАБОТКИ (Definition of Done)
- **UI/UX:** Весь интерфейс должен быть выполнен в темной инженерной стилистике (Dark Mode) с использованием шрифта 'JetBrains Mono' для технических данных.
- **Backend:** Каждая бизнес-сущность (Project, Wall, Issue) должна иметь:
  - Свой эндпоинт в API v1.
  - Описание в Swagger (аннотации в коде).
  - Миграцию в `backend/migrations/`.
- **Infrastructure:** Все пароли, порты и URL должны читаться из ENV.

## 2. ПРОВЕРКА ПЕРЕД КОММИТОМ (Verification Steps)
Перед каждым `submit` агент обязан выполнить:
1. `cd backend && go build ./...` — проверка компиляции.
2. `grep "Data Ingestion" backend/cmd/server/web/index.html` — проверка наличия продвинутого UI.
3. `swag init -g cmd/server/main.go -o docs` — обновление документации.

## 3. СТРОГИЕ ЗАПРЕТЫ
- ЗАПРЕЩЕНО использовать `AutoMigrate` от GORM или аналоги. Только SQL-миграции.
- ЗАПРЕЩЕНО оставлять старые версии файлов (например, `saas.html` или папки `static`), если они заменены на `cmd/server/web`.
- ЗАПРЕЩЕНО имитировать работу фронтенда, если он не связан с API.
